## 3. 운영점 적용 (선택 아님)

validation에서 고른 `min_cooccur=1`, `confidence ≥ 0.95`를 그대로 적용했다.
`apply_operating_point.py`는 저장된 운영점 파일이 없으면 실행을 거부하고 격자 스윕을
하지 않는다 — 재선택 경로 자체가 없다.

| | validation | sealed_test |

운영점이 무너지지 않고 옮겨갔다. sealed_test에서 화면에 뜬 관계 9건은 전부 맞았고,
사람이 봐야 할 건 14건 중 11건이 실제로 손이 필요한 건이었다.

**PPV 1.0을 "헛경보가 없다"로 읽지 않는다.** 자동표시가 9건뿐이므로 **헛경보를 관측할
기회가 9번이었다**는 뜻이다. 이 표본으로 정밀도의 하한을 주장할 수 없다.

## 4. 이 숫자들이 측정한 것의 이름

이 설정이 재는 것은 "관계를 스스로 판단하는 능력"이 아니라 **"명시된 판정 규칙을 노트에
적용하는 능력"**이다. 프롬프트의 판정 절차는 정답 라벨링 규칙을 그대로 옮긴 것이기
때문이다([tuning-log](tuning-log.md)).

그리고 development가 규칙 6개 중 4개만 담았으므로, 실제로 확인된 것은 **"조정 때 본
문형에는 규칙을 잘 적용하고, 못 본 문형에는 못 한다"**이다. sealed_test가 그것을
케이스 단위로 확인했다.

## 5. 결과 보고에 함께 적을 한계

- **SINGLE — 가설 생성 수준.** 단일 분할·단일 시드다. REPEAT·EXTERNAL·PROSPECTIVE
  어느 것도 하지 않았다(`day5 p39`).
- 교육용 합성 데이터이며 **임상 성능의 근거가 아니다.** 노트는 6개 템플릿 문형으로
  생성됐고 실제 임상 노트의 다양성이 없다.
- 노트 108건은 원본 150건의 일부다. HTML에 실리지 않은 42건은 복구할 수 없다.
- 정답 라벨은 규칙 유도(`label_origin: rule-draft`)다. 사람이 100건을 독립적으로
  판단한 것이 아니라 문형 규칙을 확인한 것이다.
- 참조표 일치율 0.70은 품질 지표가 아니다. 참조표는 세 번째 의견이고 교육용이라
  오류 항목이 섞여 있다(`reference_error_edges: 1`).
- 절제(XAI) 결과는 development·validation에서만 쟀다. sealed_test에 절제를 돌리면
  최종 세트를 두 번 보는 것이 된다.
- **`treats` 정답이 0건이다.** 노트가 약물-질병 치료 관계를 한 번도 진술하지 않기
  때문이며, 원본 그래프의 `treats` 37건에 노트 근거가 없다는 발견 자체다. 따라서
  이 평가는 `has_symptom`과 `no_relation`만 실제로 검정했다.
